# 安全约定

## 开发边界

- 不修改 DSH 应用安装包、签名或 app.asar。
- 不直接改写日常 profile 的包清单、配置、凭据或运行时数据库；安装通过受支持的插件管理机制，并先获得明确授权。
- 不读取或导入其他工具的账号凭据。测试默认使用合成数据；真实账号测试由用户参与。
- 不自动 commit、push、安装或发布。根包及新插件默认 private；UNLICENSED 表示暂未授予开源使用许可，不是已选择开源许可证。

## 凭据与权限

- 优先使用核实过的官方凭据 API；无接口时先报告限制，不偷偷退化为文件编辑。
- token、认证流程及敏感 I/O 放在受信任后端；前端只接收必要状态，IPC 使用范围明确的业务动作，不暴露任意命令或文件读写。
- 日志、错误、截图、测试 fixture、构建产物不得含真实 token、密码、授权码、完整回调或可用授权链接。
- .gitignore 是防误提交措施，不是秘密扫描器。`.env.example` 只允许虚构占位值；已被 Git 跟踪的文件不会因新增忽略规则自动安全。
- 测试结果必须准确区分本地凭据存在、刷新成功和实际业务请求完成。

## 生命周期与失败处理

需要监听器、端口或异步任务的插件必须支持资源回收、超时和适当的取消。对重复点击做互斥；失败不得误报成功或破坏原状态。并发凭据更新必须通过存储机制协调，原子 rename 本身不解决并发覆盖。

## 依赖与 CI

固定包管理器并提交锁文件。默认禁止安装生命周期脚本，任何依赖构建许可须审核后显式配置；不要为了绕过失败整体放开执行。CI 只读仓库权限，不注入个人凭据，不从 fork PR 执行有发布权限的任务。

如发现凭据泄露：先撤销或轮换，再处理 Git 历史；仅删除当前文件不能消除泄露。安全讨论中只提供脱敏信息。

## GitHub 可见性与历史

- 仓库公开前审查全部待提交内容和可达 Git 历史，不只检查工作树；历史删除过的文件仍可能暴露。
- 提交作者/提交者邮箱属于可能公开的身份信息，不是认证秘密；公开前确认是否保留。未经明确授权不重写历史、不强制推送。
- GitHub 的 public/private、package.json 的 `private: true`、是否发布 npm 包和许可证相互独立；公开可见不自动授予开源许可。
- 密钥扫描是有界、启发式检查，不构成绝对无秘密保证。测试中的 public OAuth client ID、固定 loopback 端点与明确的 synthetic 数据需同真实凭据区分。
